# 酒馆读卡扩展

这是酒馆译卡的独立 SillyTavern UI 扩展，不需要运行 Mac 应用。只帮助玩家读懂角色卡，不翻译或修改原卡，也不把解读写入聊天。

## 使用

1. 打开一张已保存的角色卡，在头像旁按钮栏的最左侧点击“读卡”。
2. 打开面板只读取资料和之前保存的解读，不调用 AI。主动点击“生成解读”才发起模型请求。
3. 解读重点包括人物设定、重要经历及其影响、玩家身份、人物关系、世界观、玩法与隐藏设定；不发送主开场白、备用开场白、群聊开场白、作者注释、标签或版本等管理信息。
4. 完成后自动保存。点“重要经历”“人物关系”等快捷问题，或输入自己的问题，可以继续追问；回答也会保存。
5. 下次打开同一张卡可以直接看已保存内容，不必重新调用 AI。卡片或关联世界书变动后会提示当前是旧解读，由你决定是否重新解读。

“读取范围”可以展开查看资料与缺失提示；回答里的 `[S数字]` 可以点击查看原文。卡片内系统指令、HTML 和脚本只作为资料，不执行，不自动加载远程图片。禁用、常驻和条件触发的世界书条目会区分，不把所有分支说成同时发生。

读取的是人物描述与经历、性格、情境、示例对白、卡片内可能参与聊天的系统/历史后设定，以及关联世界书正文和触发配置。作者注释、标签、版本等管理信息排除；世界书条目备注不当作剧情资料送给模型。正文里真正写出的玩法规则仍会解读。

## 设置

在读卡面板点击“设置”，或从酒馆的扩展设置中打开“酒馆读卡”。

默认介绍 **500 字以内**，只帮助你快速了解大概设定、角色经历、与玩家的关系和必要背景，不展开主要矛盾、心理成因或推荐玩法。有疑问再追问。未经修改的旧默认提示词会自动换成简短版；自己改过的提示词原样保留，想使用新版可点“恢复默认读卡提示词”并保存。旧解读不会自动重生成。

- **跟随酒馆当前 API**：默认沿用当前 Chat Completion（聊天补全）连接和模型，读卡任务不带聊天记录。首版不支持 Text Completion（文本补全）。
- **独立 API：自己填写**：直接填写 OpenAI 兼容 API 地址和 Key，点“拉取模型列表”后选择模型，或在始终可见的输入框里填写完整模型 ID。不需要先保存、先选模型或先建立酒馆连接档案。只填域名时补 `/v1`，已有路径/版本前缀原样保留，完整 `/chat/completions` 地址会转成接口前缀。通过酒馆后端请求，不需要服务商为浏览器开放跨域访问，不切换聊天连接。
- **独立 Key 的保存边界**：地址和模型点“保存设置”后持久保存；Key 只在当前页面内存中保留，正常重开设置可以继续使用，刷新或退出酒馆后需要重填。Key 不写入扩展设置、浏览器存储或结果文件，也不改酒馆聊天的 Key。空 Key 仅复用本页同一地址已保存的 Key，换地址不借用旧 Key；无密钥的本地接口可留空。
- **手机或刷新后提示 Key 未填写**：Key 不会跨设备同步。点错误下方“打开 API 设置补填 / 检查”，在本设备填写 Key 并保存后再提问，不需要重新读卡；明确无需 Key 的接口可勾选“接口无需 Key”。认证、额度和网络错误会显示接口提供的原因，没有自动重试或切到聊天 API。
- **酒馆已保存的连接配置**：这是旧版 `profile` 模式，另列为第三项，已有配置不丢失。先在酒馆中保存 Chat Completion 连接，再在这里选用；需要密钥时在酒馆中绑定，未绑定不借用当前聊天 Key。使用反向代理的档案仍需手填模型，不借用当前聊天的代理密码。
- **用于读卡的模型**：设置里显示所选连接与完整模型名。跟随/档案模式默认沿用连接模型，也可另选或手填；独立 API 模式直接填写或从列表选。拉取列表使用当前表单的地址和 Key，不保存草稿、不发送角色材料、不调用生成，也不自动选第一个模型。失败后仍可手填模型，不悄悄换连接。
- **生成参数**：默认使用酒馆当前的温度、Top P、频率惩罚和存在惩罚；独立连接也沿用这四项，不导入聊天预设或提示词。取消勾选后可单独调整读卡参数。单次最大输出 token 始终按此处填写的值。只影响读卡和追问，不更改酒馆聊天参数；服务商可能不支持某些参数，实际错误会显示。
- **流式生成**：默认开启“流式生成（边生成边显示）”，三种连接模式都可使用。小卡介绍/追问直接读取原文，一次请求完成；长卡仍完整分段读取，只在最终汇总时显示流式预览。预览未完成时不保存，正常结束才自动保存；停止、断流或失败保留旧结果。接口不支持流式时可关闭开关再手动尝试，不自动重复请求；接口自行返回完整 JSON 时也能正常读取。
- **系统提示词**：非空时原样作为唯一 `system` 消息；清空则不发送系统提示词。不写入卡片的 `system_prompt`。
- **读卡提示词**：可以编辑。“恢复默认读卡提示词”只恢复这一项，不动系统提示词；点击“保存设置”后生效。
- **分块与快捷问题**：可调整文字预算与每行一个的快捷问题。文字预算以字符估算，不是精确 token。

长资料会完整分段读取并汇总，可能产生多次计费请求。进度会显示实际分段范围，不以截断后的局部资料冒充已读完。模型仍可能误解，应通过原文来源核对重要设定。

任务进行中请不要更换或删除酒馆连接及密钥。扩展会检查可见的服务商、模型、端点和档案标识是否变化，但跟随模式无法从宿主上下文可靠发现同一端点的活跃密钥轮换。

## 保存与注意事项

解读、追问和对应来源快照保存在酒馆用户文件中，与原角色卡、世界书和聊天分开。正常刷新或重新打开仍可查看。删除酒馆用户数据或插件自己的保存文件会导致结果丢失，备份酒馆时也应保留这些用户文件。

保存失败会显示“尚未保存”，结果保留在当前窗口，可以点击“保存”重试；不要在重试成功前刷新。生成失败或停止不会清除之前保存的解读。未保存提示词和未发送问题仅在当前窗口保留，刷新或退出前有浏览器提示。

“重新解读”成功后会替换这张卡保存的解读与追问，失败或停止时旧记录不变。首版不提供多版本比较。

默认读取角色卡与其绑定的主/额外世界书，不将所有全局、Persona 或聊天世界书混进来。不执行世界书触发器或自动化脚本，也不改变条目的启用状态。

## 手机使用

扩展安装在酒馆里，不需要给手机另装应用。手机浏览器访问同一个酒馆、登录同一用户后，也从角色头像旁的“读卡”进入；保存的解读随酒馆用户数据保留，不局限于当前手机或浏览器。

小屏和横屏使用不透明、可滚动的弹窗，长名称自动换行，主要操作按钮加大，提示词输入区保持易读字号；窄屏参数区排成单列。设置、原文来源与主面板都可上下滚动。手机布局验证使用 320×568 与 844×390 的模拟视口，覆盖插件弹窗与扩展更新控件；尚未实测实体手机及软键盘，也不保证酒馆宿主整页没有横向溢出。

也处理了手机通过局域网 HTTP 地址打开酒馆时的保存兼容：不会因浏览器缺少部分接口而无法辨认原有记录，不需要丢掉之前的解读。扩展不会为手机访问更改酒馆的网络或登录设置。

## 从酒馆安装（推荐）

1. 打开酒馆顶部的“扩展”，点击“安装扩展”。
2. 粘贴这个仓库地址：**https://github.com/qijiu79-79/jiuguan-reader**。
3. 使用默认分支，通常选择只为当前用户安装；全局安装由管理员安排。
4. 安装后从角色头像旁点“读卡”。不需要下载源码、运行 Mac 软件或填写 GitHub Token。

这是独立的扩展仓库，不是酒馆译卡桌面项目的上游仓库。仓库根部已有可运行的 `manifest.json`、`index.js` 和 `style.css`，酒馆可以直接安装；完整对应源码在仓库的 `source/` 中。

## 一键更新

打开酒馆顶部的 **“扩展程序”**，展开 **“酒馆读卡”**，直接点击 **“一键更新”**。更新按钮只放在这个扩展面板内，不需要打开读卡设置弹窗。检查、下载、最新版本和错误信息直接显示在按钮下方，不另外弹确认框。

插件会核对当前安装来自上述发布仓库，然后沿用酒馆的扩展更新接口检查和下载当前安装分支的更新；不会切换聊天连接、调用 AI 或删除已存解读及提示词。

- 下载更新不会清除草稿，也不会中断当前读卡、追问或保存；有未保存输入时仍可下载，不要求先删掉或提交草稿。
- 下载完成后，在同一个扩展面板显示“刷新页面”。只在刷新前检查插件草稿与运行任务；先保存酒馆其他页面和扩展中未提交的输入，再点该按钮生效。不加二次确认框，也不擅自自动刷新。
- 全局安装的更新需要酒馆管理员权限；网络或权限错误会用中文显示，可重试。
- 下载请求超时或连接中断时，不会盲目重复拉取。再次点击先复查；确认服务器完成后提示刷新，仍未确认则说明应稍后检查。
- 手动解压 ZIP 的安装没有 Git 记录，不能一键更新，不会被误报为“已最新”。请保留酒馆用户数据，按下面的迁移说明改为仓库安装。

同一个插件也可使用酒馆“管理扩展”中的更新按钮。安装及更新需要运行酒馆的设备能连接 GitHub，并已安装 Git；插件本身不改变酒馆的网络或登录设置。

如果仍在使用 0.1.2 或 0.1.3，旧版按钮可能因未保存输入而阻止下载。此次可从酒馆“管理扩展程序”找到“酒馆读卡”并更新；先保存输入，再刷新应用新版。0.1.4 起已将下载与刷新保护分开，不再要求处理草稿才能下载。

来源核对适用于酒馆常规的单 `origin` 仓库安装，不是防止管理员修改本机 Git 配置的安全边界。自行更改多个远端或镜像配置时，请由管理员核对更新来源。

酒馆按 Git 提交检查更新，文档或样式修订也可能触发下载，版本号不一定每次改变。“当前版本”显示的是当前页面已加载的插件版本；下载完成不等于页面已经刷新。

## 本地 ZIP 安装与迁移

首版最低声明 SillyTavern **1.19.0**，已在该版本的隔离酒馆、本机假模型与虚构角色卡上实际验证；尚未验证旧版或真实服务商兼容，不会自动升级你的酒馆。

构建输出是一个完整扩展文件夹，不是桌面应用：

```text
dist-extensions/jiuguan-reader/
├── manifest.json
├── index.js
├── style.css
├── README.md
├── LICENSE
└── THIRD_PARTY_NOTICES.md
```

解压交付包后，把其中的 `jiuguan-reader` 文件夹放入目标 SillyTavern 的 `public/scripts/extensions/third-party/`，再刷新页面。多用户部署也可放入 `data/<用户句柄>/extensions/jiuguan-reader`，由酒馆管理员安排。不要把源码 `src/` 文件夹直接当成可安装扩展。

本地 ZIP 不是酒馆“安装扩展”接受的 Git URL。若已手动安装旧版，先保存所有输入并备份酒馆用户文件，关闭酒馆后将原来的 `jiuguan-reader` 插件文件夹移到插件扫描目录外保留，再启动酒馆、从上述仓库安装到相同范围。不要删除酒馆用户数据、读卡保存文件或扩展设置；插件识别键不变，重开原角色卡可继续查看已保存内容。遇到同名目录已存在时不要强行覆盖或删除 Git 记录。

不要同时在全局目录与当前用户目录保留同名 `jiuguan-reader` 插件。旧的全局副本可能遮住已经更新的用户副本，出现“更新成功但页面仍是旧版”。只保留一种安装范围；如有另一份旧副本，将其移到插件扫描目录外备份，不删除用户数据或解读保存文件。

安装到已有酒馆前先保存未保存的输入；本项目不会自动查找或改动你的正式酒馆。

## 开发

在酒馆译卡项目根目录使用 Node.js 22 与 npm；独立发布仓库则先进入 `source/`：

```bash
npm ci
npm run test:reader-extension
npm run build:reader-extension
npm run package:reader-extension
```

源码位于 `extensions/jiuguan-reader/src/`，复用 `server/tavern/reader-domain.ts` 的资料整理、无损分块和引用校验。桌面版的入口和读卡默认行为保持不变。

打包命令在 `dist-extensions/` 生成安装 ZIP、对应源码 ZIP 和校验文件，还生成一个全新的 Git 发布目录：根部是可安装扩展，`source/` 是完整对应源码。全部交付仅从明确的文件白名单生成，不复制本地工作区历史、用户卡片、配置或密钥；打包不自动上传。

兼容性验证使用 SillyTavern 1.19.0 的隔离环境、虚构角色卡与本机假模型，覆盖读卡、追问、保存恢复、提示词、连接选择和 Git 更新。尚未验证旧版酒馆、真实服务商、实体手机及软键盘；声明最低版本不代表这些环境均已实测。

API 接入与扩展面板内更新的交互参考 **LittleWhiteBox by biex**，并核对酒馆助手的更新入口；未复制这些项目的实现。宿主能力依据 SillyTavern 官方扩展接口。与小白自动刷新的方式不同，本插件保留手动刷新，以便先保存其他输入。
